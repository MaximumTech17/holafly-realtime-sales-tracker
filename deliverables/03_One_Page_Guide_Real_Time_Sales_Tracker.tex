\section{Architecture \& How Auto-Refresh Meets the $\leq 10$-Minute Target}
\textbf{Why legacy Looker Studio lags 3--5 hours:} Reporting stacks three bottlenecks---multi-hour batch ETL syncs from checkout/Intercom, scheduled full-table BigQuery rebuilds, and Looker Studio's default 12-hour data freshness cache.
\begin{itemize}[leftmargin=1.15em, itemsep=1.4pt, topsep=1.5pt, label=\hbullet]
  \item \textbf{MVP Streaming Architecture (1--3 min end-to-end latency):} A deterministic Python generator (\code{src/mock\_generator.py}) ingests realistic eSIM micro-batches every \textbf{2 minutes} into an ACID SQLite WAL store (\code{raw\_orders}). ANSI SQL window views (\code{sql/views.sql}) clean and deduplicate every row in $<15$\,ms, and the Streamlit cockpit (\code{app.py}) auto-refreshes every \textbf{60 seconds} via \code{@st.fragment(run\_every="60s")}.
  \item \textbf{24/7 Cloud Autonomy (Local PC Off):} Hosted on Streamlit Community Cloud using deterministic UTC time-bucket seeding (\code{BASE\_SEED + floor(epoch/120)}). On every 60s heartbeat or evaluator load, the app creates/syncs the SQLite stream up to \code{UTC NOW()} in $<200$\,ms without any local process.
  \item \textbf{Production Mapping at Holafly:} Replace mock ingestion with \textbf{Checkout/Intercom Webhooks $\rightarrow$ Pub/Sub $\rightarrow$ BigQuery Storage Write API (Streaming Inserts)}, execute the exact 4-gate SQL inside an \textbf{Incremental BigQuery Materialized View} scanning only the trailing 24h partition ($<5$\,MB/run), and serve via \textbf{BI Engine / Looker Studio} or a \textbf{Cloud Run} tactical cockpit.
\end{itemize}

\section{``What Counts as a Sale?'' --- Formal 4-Gate SQL Data Quality Standard}
Every incoming event in \code{raw\_orders} passes four sequential SQL classification gates (\code{v\_classified\_orders} $\rightarrow$ \code{v\_valid\_sales}). Rejected payloads remain fully transparent in the top \textbf{Pipeline Telemetry Strip} and the \textbf{Data Quality \& SQL Audit} tab:

\section{Timezone Standard, Interactive Demo Controls \& Known Refresh Limitations}
\begin{itemize}[leftmargin=1.15em, itemsep=1.4pt, topsep=1.5pt, label=\hbullet]
  \item \textbf{Timezone \& Midnight-Safe 3-Shift Model:} Stored in ISO-8601 UTC; displayed in \textbf{COT (UTC-5, Medell\'in Hub)} by default (switchable to UTC or CET) across \textbf{Morning (06--14 COT)}, \textbf{Afternoon Peak (14--22 COT)}, and \textbf{Night (22--06 COT)}. All shift boundaries and elapsed-hour calculations use full UTC timestamps so \code{SHIFT\_3\_NIGHT} spans midnight cleanly without splitting pre-midnight records.
  \item \textbf{False-Alarm Guard \& Interactive Controls:} Alerts require a trailing 3h baseline of $\geq 10$ valid orders/30m to suppress noise on small filtered slices. Evaluators can switch the sidebar \textbf{Operational Scenario Mode} (Default Active Drop, Normal Baseline, Critical Outage, Flash Surge) or click \textbf{Simulate +2m Batch} to verify live ingestion immediately.
  \item \textbf{Free-Tier Cloud Limitation:} Streamlit Community Cloud free containers sleep after 12+ hours of zero visitors ($\sim$15--25s cold wake-up, followed by $<200$\,ms deterministic database rebuild and catch-up). Deploying on \textbf{Google Cloud Run (\code{min-instances=1})} eliminates cold starts completely in production.
\end{itemize}
